# The loop (Phase 5) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Three inputs stop being what the user typed once and start being what the app measured — the night of the stretch counts itself from the archive, the reflection's one adjustable answer writes an `overrides` entry instead of overwriting a quiz answer about the user's body, and the sleep goal is proposed once against five nights of evidence with a refusal that sticks.

**Architecture:** `stats.js` grows two pure functions, `countStretch` (a walk back from tonight that bridges one missing night and stops at two, seeded by the quiz answer until the first measured break) and `sleepBand` (the four-way split `planSummary` already makes, named once). `App.jsx` builds a second profile — `planProfile`, `{ ...profile, stretch }`, derived on every render and never stored — and plans, renders and folds with it, while both write exits go through `stored(profile)`, one expression that drops the key. `planner.js` gains a precedence clause on `stretchNight` and a table, `reflectionAdjust`, that turns the reflection's answer into `{ key, value, msg }` set from the plan's own default. `Dashboard.jsx` gains one `if` in the "Keep current" handler. **`generateTimeline` does not change; its signature stays `(profile, logs, now)`.**

**Tech Stack:** Plain ES modules, React 18, Vitest 2, `localStorage`, Playwright (already in `node_modules`, driven by hand — not a test runner). No new dependencies.

## Global Constraints

- **No new dependencies.** Nothing added to `package.json`. Playwright is already installed and every existing driver is run with bare `node`.
- **Do not change `generateTimeline`.** It stays `(profile, logs, now)`. `planner.js`'s only edits are one line inside `stretchNight` and one new table plus one new function beside `ADJUSTABLE`. Nothing inside `generateTimeline` moves — including the `changed` line `caff-cutoff` still does not have.
- **Do not store the derived count.** `gy.v1`'s profile must never contain a `stretch` key. `stored()` at the write effect and at `exportData` is the whole guard, and it is a trust boundary rather than tidiness: a stored `stretch` is read back by `forNight` → `archived` → `foldNight` on boot, the one fold that never sees the memo.
- **One new stored field, and only one.** `sleepGoalAsked` on the profile. `gy.v1`'s top-level keys stay exactly `night,profile,logs,reflection,theme,archive`.
- **The rule is: the app plans, renders and folds with `planProfile`, and persists with `stored(profile)`.** No per-component judgement calls. The four exceptions are named in Task 2 and are exactly: the two `nightOf(calculateShiftPhases(profile))` calls (which read only `shiftStart`, `shiftEnd`, `plannedSleep`, `sleepGoalHours`) and the two write exits.
- **Every value that reaches the plan is clamped, and the clamp is stated.** `countStretch`'s seed is `Math.min(4, Math.max(1, Math.round(seed) || 1))` — the range the quiz can express. `reflectionAdjust`'s value is `Math.min(ADJUSTABLE[key].max, Math.max(Number.isFinite(cur) ? cur : -Infinity, derived))` — never above the slider's ceiling, never below a number the user set by hand, and never poisoned into `NaN` by an override that is not a number. The failure direction in both cases is *toward the user's stated intent*: someone who opened this app wants to be protected on a stretch, and someone who asked for an earlier cutoff does not get it walked back.
- **Never simplify away the design system.** Every element of the receipt card is an existing component on the app's `T` tokens: `Card`, `Btn`, `Eyebrow`, the already-imported `ArrowCounterClockwise`, `ADJUSTABLE`'s own label/unit/decimals. The row shape is copied from the reminders list (`App.jsx:1923`) and the button from the adjust sheet's reset (`App.jsx:2255`). No new component, no new token, no `alert`, no unstyled control.
- **Vitest runs in `environment: "node"`** (`vitest.config.js`), include glob `src/**/*.test.js`. There is no DOM and no `localStorage`. `App.jsx` reads `location` at module scope and does not import under this environment — which is why `reflectionAdjust` lives in `planner.js` and not beside `REFLECT_QS`.

- Produces:
  - `countStretch(archive: NightRecord[] | null | undefined, tonight: string | undefined, seed: unknown) -> number` — exported from `src/stats.js`. Which night of the current stretch tonight is, counted back from `tonight`. Always `>= 1`. Task 2 calls it.
  - `sleepBand(h: number) -> 4.5 | 5.5 | 7.5 | 9.5` — exported from `src/stats.js`. Tasks 5 calls it, from both `readPatterns` and `App.jsx`'s `planSummary`.
- Neither function has a caller at the end of this task. That is deliberate and is what makes the task independently reviewable.

**Background the implementer needs:**

`nightInStretch` is written in exactly one place — `finishQuiz` (`App.jsx:2462`), from the question at `App.jsx:454` — and **nothing writes it again.** It is not in `REVIEW`, not in the profile sheet, not in the adjust sheet. Whatever a user answered on the day they installed the app is the night the plan believes it is, permanently, and the default is `1`. So the bar is not "a derived count beats a remembered one"; it is "a derived count that is sometimes wrong beats a frozen one that is wrong every night after the first".

**The rule: one missing night does not break a stretch. Two do.** The two error directions are not symmetric. Undercounting removes protection from someone four nights deep (cutoff an hour later, resets 15–30 minutes further apart, check-in not weighted). Overcounting asks a rested person to stop caffeine an hour early. The house rule is to fail toward the user's stated intent, and the stated intent of someone who has opened this app at all is to be protected on a stretch — so the bridge goes to the side that keeps counting. It also fits the data: rosters give two or more nights off together, so a single hole mid-run is far more likely to be a night nobody opened the app.

**Why the quiz answer is a seed and not a fallback.** The cheap version — derived count when the archive has something, quiz answer when it does not — makes a user who installed on night three watch the app count **3, 2, 3, 4** and the caffeine cutoff relax by an hour on night four. Adding `first - 1` gives 3, 4, 5, 6. The case is in Step 1 as "the day-two regression".

The seed expiring by itself, the offsets-rather-than-ids choice and the loop's termination are all argued in the docblock in Step 3, which is the copy that ships. Read it there rather than twice.

**Why `sleepBand` lands here with no caller.** It is two lines and it is the shared definition Task 5 needs in two files at once (`readPatterns` proposes a band, `planSummary` names the plan type for it). Landing it with its fixed-point tests first means Task 5 is a wiring task rather than a wiring-plus-arithmetic task, and the fixed-point property — `sleepBand(x) === x` for each of 4.5, 5.5, 7.5, 9.5 — is what makes `sleepBand(avg) !== goal` a complete trigger with no tolerance to tune. **Do not touch `planSummary` in this task.** Task 5 rewires it, and until then the duplication is visible rather than half-removed.

```js
/** Which night of the current stretch tonight is, counted back from tonight.
    One night with no record is bridged, two end the run. The quiz answer seeds
    the nights that were already behind you when the archive starts, and counts
    only while `n - 1 === back.size` — true exactly while the walk has absorbed
    every record, which is to say while no break has ever been measured.
    Offsets rather than ids so the only date maths is daysBetween: a hand-edited
    id gives NaN and fails `> 0`, a duplicate lands in one Set slot, and a
    future-dated record is excluded by the comparison the day strip already uses.
    ponytail: the bridge is an unmeasured heuristic, argued in the spec from
    rosters. Upgrade path is `workDays`, once a real archive shows the
    distribution of gap lengths. */
export function countStretch(archive, tonight, seed) {
  const back = new Set(
    (archive || []).map((r) => daysBetween(tonight, r.id)).filter((d) => d > 0)
  );
  /* Clamped to the range the quiz can express: this comes off a profile a
     hand-edited blob can write anything into, and an unclamped 999 gives night
     four's plan to someone on night one, forever. The `|| 1` is the other half
     of the same boundary — NaN from a missing or unparseable seed is falsy, and
     so is the 0 that is not a night. */
  const first = Math.min(4, Math.max(1, Math.round(seed) || 1));

  /* Terminates without a cap: past the oldest record every step is a miss, so
     the second one always arrives. */
  let n = 1, miss = 0, d = 1;
  while (miss < 2) { if (back.has(d)) { n += 1; miss = 0; } else miss += 1; d += 1; }

  return n + (n - 1 === back.size ? first - 1 : 0);
}

/** The four values the quiz can express, and the cuts planSummary already bands
    on. sleepBand(x) === x for each of them, which is what makes
    `sleepBand(avg) !== goal` a complete trigger with no tolerance to tune. */
export const sleepBand = (h) => (h <= 5 ? 4.5 : h <= 6.5 ? 5.5 : h <= 9 ? 7.5 : 9.5);
```

**Background the implementer needs:**

`generateTimeline(profile, logs, now)` cannot see the archive and is not being given it. So the count has to arrive on the profile, and the app builds a second one.

**Everything in the render tree gets `planProfile`. Not a subset.** `PlanTab` computes `movementInterval(profile)` for the recurring card's "every N minutes" (`App.jsx:1420`). `Dashboard` hands the profile to `readPatterns`, whose caffeine adjustment computes `caffeineHours(pr) + 1`. `foldNight` writes `moveTotal` and `cutoff` into the record from the same two functions. Hand any of them the seed while the plan was built from the count and the screen disagrees with itself by an hour and by thirty minutes. A rule with exceptions is a rule somebody gets wrong at 3am.

**The cost of that rule is that `setProfile` bases are now planProfile-derived**, so a `stretch` key can ride into profile state and out to `gy.v1`. Harmless in state — the memo overwrites it on the next render. Not harmless on disk, for the reason in `stored()`'s own comment in Step 5e. One expression at the two paths that leave the app is smaller than an audit of six `setProfile` call sites that has to be re-run every time somebody adds a seventh.

Two things about the wiring are argued in the code comments in Step 5, which is the copy that ships: why `now` is in the memo's dependency list (5f), and why the tick's fold takes `planProfile` while the tick effect's dependency list must not (5h). Read them there.

**`boot`'s fold cannot have it**, and that is fine. `forNight` runs at module scope with the stored profile, so a night folded on boot is folded at the seed's count. That is Phase 2's "last night is folded against tonight's profile" ceiling, one field wider. **Do not fix it by storing the count.**

**Why there is no stretch editor.** It looked obligatory and it is not. When the count is wrong — the archive says night one because the user worked three nights without opening the app — the two numbers it would have moved are already adjustable by name, with a live preview and a reset: `caffeineHours` on `caff-window` and `caff-cutoff`, and `moveGap` on every `move-N` and on the recurring card. A stretch control would be a third route to the same two numbers, it would have to be an override, and an override on the stretch is exactly the frozen number this task exists to delete — it would have to expire at the rollover, which no other override does.

```js
/* What the reflection's one adjustable answer means, in plan numbers. Set from
   the plan's own default rather than stepped from the current value, so
   pressing Save twice does not move it twice and answering the same thing on
   four nights running does not walk the caffeine cutoff off the end of the
   scale. `no` returns the sentence to say instead, for the profiles on which
   the number would reach no item. */
const REFLECTION_ADJUST = {
  "Earlier caffeine cutoff": {
    key: "caffeineHours",
    to: (p) => caffeineHours(baseProfile(p)) + 1,
    say: (v) => `Caffeine now stops ${v} hours before sleep.`,
    no: (p) => p.caffeine === "none" && "Caffeine is already off your plan, so there is nothing to move earlier.",
  },
  "Fewer resets": {
    key: "moveGap",
    /* +30 and not +15: one step of 15 removes at most one reset from a whole
       shift, which reads as nothing happening and gets asked again tomorrow.
       The reflection is a once-a-night control, not a slider. */
    to: (p) => movementInterval(baseProfile(p)) + 30,
    say: (v) => `A reset every ${v} minutes now.`,
  },
  "More rest": {
    key: "restLength",
    /* 30 flat rather than a step: it is the ceiling deep-rest's own `why`
       already names, so it is the most rest the plan is willing to recommend. */
    to: () => 30,
    say: (v) => `Rest blocks are now ${v} minutes.`,
    no: (p) => p.nap === "none" && "You said naps are not possible, so the plan keeps rest short and quiet instead.",
  },
};

/** { key, value, msg } to apply, { key: null, msg } to explain, or null. */
export function reflectionAdjust(profile, answer) {
  const a = REFLECTION_ADJUST[answer];
  if (!a) return null;
  const no = a.no && a.no(profile);
  if (no) return { key: null, msg: no };
  /* Only an existing NUMERIC override holds the floor. Not the derived default:
     that would need restLength's per-item defaults (25, 20 or 15) to collapse
     into one number, and there is no honest one. Not `cur ?? -Infinity` either:
     `overrides` comes off a hand-editable blob, Math.max("x", 150) is NaN, ov()
     hands NaN to the planner as a real value, and a NaN reset gap emits zero
     movement resets for the whole shift. A floor that is not a number is not a
     floor.
     One Math.max covers all three keys because all three ask for a LARGER
     number — stop caffeine earlier, wait longer between resets, rest longer. An
     answer that asked for a smaller one would silently no-op here. */
  const cur = (profile.overrides || {})[a.key];
  const value = Math.min(
    ADJUSTABLE[a.key].max,
    Math.max(Number.isFinite(cur) ? cur : -Infinity, a.to(profile))
  );
  return { key: a.key, value, msg: value === cur ? "That is already where your plan is." : a.say(value) };
}
```

## Known ceilings

Record these; do not close them in this phase.

- **Two or more unlogged nights inside a real stretch reset the count.** The measured break wins, the plan drops back to night one, and the caffeine cutoff moves an hour later for someone who is five nights deep. The recourse is the two adjustable numbers; the fix is `workDays`, and its condition — an archive showing unlogged nights distorting a real number — is still not met.
- **A night off on which anything was logged counts as a worked night.** Requiring evidence of a shift (`endShift` is on every record since Phase 3) was considered and rejected: most users never tap it, so the strict rule would undercount, which is the unsafe direction.
- **The bridge is a heuristic, and it is unmeasured.** One night forgiven, two not, on an argument about rosters rather than on data. The thing to look at when there is a real archive is the distribution of gap lengths.
- **The count is ±1 across a bridged night.** It reads low, and only matters when it lands on 2, 3 or 4 exactly.
- **A night folded on boot is folded at the seed's count**, not the archive's, because `forNight` runs at module scope with no memo. Phase 2's ceiling, one field wider.
- **An override outlives the reason it was written.** "Earlier caffeine cutoff" on night 3 sets a number that includes the stretch's own +1, and it stays after the stretch ends. Visible in the receipt card, undone in two taps, not expired automatically.
- **`sleepGoalAsked` is unvalidated**, like every other field in `gy.v1`. A hand-edited value only ever suppresses or fails to suppress a proposal.
- **Applying the sleep goal can merge two nights into one record**, when the new wake boundary moves backward across the current clock. Phase 3's accepted cost, now reachable from a button rather than only from the shift-time sheet.
- **The caffeine cutoff still does not say why it moved an hour.** The count is explained on the Plan tab and in the fatigue check-in's `changed` line, but the item that actually changed carries no reason, because writing one edits `generateTimeline`.
- **A hand-edited archive is still unvalidated.** `countStretch` tolerates garbage rows without throwing, which is one function's worth of hardening against a ceiling that stands unchanged.
- **`?seed` shows the real stretch count**, not a fabricated one: the 45 mock nights live in `history`, `countStretch` reads `archive`. Deliberate — a fabricated stretch would move a real caffeine cutoff.
